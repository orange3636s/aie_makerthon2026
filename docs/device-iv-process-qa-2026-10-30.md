# 공정 레시피와 I–V 연동 검증

## 발견한 문제와 수정

기존 커밋 `aef90a7`의 모델을 별도로 실행해, 같은 형상에서 `net_active`를 2배로 바꾸었을 때 FET 10종의 전류 배열이 완전히 동일함을 재현했다. 기존 코드는 S/D 활성 농도를 통과 조건으로만 사용했다. PN 접합은 이미 농도를 수치 계산에 사용하고 있었다.

수정 후 FET은 계산된 순 활성 농도의 깊이 적분으로 접근 면저항을 구한다. 게이트 양옆 각각 100 nm 구간을 평균하며 `Rsh = 1/(q μ Nsheet)`, `Rs,d = Rsh × 100 nm / W_eff`를 적용한다. `Vgs,int = Vgs − I Rs`, `Vds,int = Vds − I(Rs+Rd)`를 square-law와 함께 이분법 60회로 푼다. CFET의 두 Si 영역과 극성은 분리한다.

게이트 절연막 두께/EOT는 원래 계산된 형상을 사용하고 있었으며, 이번에는 실제 증착 레시피를 변경해 확인했다. S/D 농도를 채널 배경 농도로 대체하지 않았다. 배경 농도, 이동도, 유효 폭, Vfb는 여전히 명시적인 입력 가정이다.

CFET의 n/p 전류 크기 차이로 작은 곡선이 평평하게 보이던 문제는 두 그래프의 축을 분리해 개선했다. 각 곡선의 현재/목표는 같은 축에서 비교한다.

## 검증 방식

- `node tests/device-iv.cjs`: 11종 단위 검증, FET 활성 농도 2배 → 접근 저항 절반/전류 증가, CFET 상부 p 농도만 변경 → 하부 n 곡선 불변.
- `node tests/device-iv-process.cjs`: HTTP `/api/reverse`로 전체 공정을 실제 재계산. 기본값, 주입량 2배, 각 Anneal 시간 1 s, 게이트 절연막 증가를 비교. PN의 마지막 변형은 보호 산화막 증착 시간 1.25배이며, 전류가 변하지 않아야 한다.
- 기존 예시 캐시와 혼동하지 않도록 모든 native 비교에 기판 두께 501 nm를 동일하게 적용했다. 각 입력 JSON의 SHA-256와 최종 프레임을 `.runtime/iv-process`에 보관한다. 재실행은 동일 입력의 실제 계산 결과를 재사용하며 `--fresh`로 새 계산을 강제할 수 있다.
- `node tests/device-iv-recipe-browser.cjs`: Chrome에서 MOSFET 주입량 입력, 공정 계산 버튼 실행, 최종 단계 선택, I–V 다시 열기까지 실제 UI 흐름 검증.
- `node tests/device-iv-browser.cjs`: 11종 그래프/입력/초기화/잘못된 입력/빈 Wafer, CFET 두 축, 1440/768/390/320 px 및 pageerror 검사.

## 해석 범위

교육용 등가 모델이며 TCAD 검증 모델이 아니다. 접근 길이 100 nm, 균일한 이동도, 대표 EOT 유전율은 가정이다. 실제 2D 전류 경로, 금속 접촉저항, 도핑 의존 이동도, 누설·단채널·양자효과를 해석하지 않는다. GAA/CFET의 극도로 작은 전류도 추정 접근 저항의 결과이지 제조 가능한 소자의 성능 보증이 아니다.

단순 열확산으로 활성 면밀도가 거의 보존되면 전류 변화가 작거나 부호가 기대와 다를 수 있다. 모든 파라미터 변경에 임의의 전류 변화를 부여하지 않는다. PN의 보호막은 MOS 게이트가 아니므로 보호막 두께를 게이트 용량처럼 적용하지 않는다. Charge Trap은 저장/소거 상태를 계산하지 않는다.

계산 기준: [NIST 면저항·이동도](https://www.nist.gov/pml/nanoscale-device-characterization-division/popular-links/hall-effect/hall-effect), [ngspice MOS 직렬 저항](https://ngspice.sourceforge.io/docs/ngspice-45-manual.pdf). 이 라이브러리들을 새로 실행 엔진에 연결한 것은 아니다.

## 실제 실행 결과

44개 조건 모두 native 계산 성공 및 유한한 I–V 생성. 아래는 기본 조건 대비 마지막 전압 점의 전류 변화율이다. FET은 |Vgs|=3 V, |Vds|=0.1 V, PN은 V=0.6 V. CFET은 n/p 순서이며 p 전류는 절댓값 변화율이다.

| PN Junction | -49.754% | -10.949% | 0.000% |
| MOSFET | +15.190% | +0.181% | -27.475% |
| FD-SOI | +14.390% | -0.011% | -28.617% |
| PD-SOI | +12.507% | -0.011% | -30.422% |
| RCAT | +55.375% | -1.907% | -25.559% |
| BCAT | +86.884% | -0.029% | -3.958% |
| FINFET | +97.091% | -0.007% | +15.042% |
| GAAFET | +96.825% | -0.008% | -0.794% |
| MBCFET | +97.023% | -0.018% | -0.753% |
| Charge Trap | +1.486% | +0.002% | -32.097% |
| CFET n / p | +96.825% / +99.984% | -0.009% / -0.748% | -0.794% / +0.306% |

ALD SiO₂는 10 cycles 추가, CVD HfO₂는 증착 시간 1.5배로 변경했다. Charge Trap은 tunnel/blocking 산화막 둘 다, CFET은 두 게이트 절연막 모두 변경했다. 전체 후속 공정을 다시 계산하므로 절연막뿐 아니라 후속 주입 분포와 접근 저항도 달라진다. FINFET에서는 EOT가 3.907→5.859 nm로 증가했지만 추정 Rsd가 27.067→23.266 kΩ로 감소해 전류가 증가했다. 이를 '산화막이 두꺼울수록 전류가 증가한다'는 보편적인 물리 경향으로 해석하면 안 된다. 표는 모델 연동 확인이지 실측 정확도 검증이 아니다.

통과: `npm test` 28개 스크립트, `npm run build`, 11종 브라우저 회귀, 실제 MOSFET 레시피 입력/재계산/그래프 갱신, 44개 native 조건. 잘못된 900°C 입력은 API가 허용 범위(950–1100°C) 밖으로 거부했으며 이후 열처리 시간 변형으로 검사했다.

이번 로컬 전체 공정 재계산은 23.4–136.4 s였다(병렬 테스트 부하 포함). 15 s 이내 계산을 보장하지 않는다. 별도의 I–V 후처리만 Node 24에서 소자당 10회 평균 약 0.7–4.3 ms였으며 브라우저/모든 PC 성능 보증은 아니다. 모든 44개 결과의 최초 서버 응답은 `cached:false`였고 최종 통합 재검증은 입력 및 native 엔진 해시가 일치하는 저장 프레임을 재사용했다.
