# 위키 관리 규칙

이 폴더를 편집하는 사람과 LLM이 함께 사용하는 규칙이다. 작업은 로컬 또는 GitHub 문서 편집으로 수행한다.

1. **자료 등록(ingest)** · 재사용할 수 있는 자료인지 확인하고 `raw/`에 프로젝트 파일 경로와 기준 커밋를 기록한다. 기존 원천 기록은 보존한다. 자료가 기존 설명을 바꾸면 새 해설을 중복 생성하기 전에 관련 페이지를 갱신한다. 공정 간 연결과 프로젝트 자체 실습을 우선한다.
2. **질의(query)** · [색인](wiki/index.md)에서 관련 페이지 두세 개를 골라 읽는다. 기초 이론, 교육용 근사, 예제에서 계산된 사실, 아직 확인할 가설을 나눠 답한다. 결과를 재사용할 가치가 있으면 근거와 함께 새 사례 페이지로 정리한다. 자료가 없으면 수치를 만들지 않는다.
3. **점검(lint)** · 색인 누락, 끊긴 링크, 고립된 페이지, 동일 ID, 단위와 수치 불일치, 모델 버전 혼동을 확인한다. 모델이나 기준 레시피가 바뀌면 기존·신규 버전의 차이를 명시한다. 충돌하는 근거가 있으면 둘 다 남기고 어떤 조건에서 차이가 생겼는지 기록한다.
4. **변경 기록** · 새 페이지나 의미 있는 수정을 색인에 반영하고 [로그](wiki/log.md) 끝에 날짜·작업·검증 내용을 추가한다.

페이지에는 질문이나 주제, 설명, 적용 범위, 관련 페이지, 출처를 둔다. 기존 `cards.json`은 여덟 기초 카드의 구조화된 요약으로 유지한다. 같은 공식을 바꾸면 Markdown과 JSON을 함께 확인한다.
